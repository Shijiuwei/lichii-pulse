Upstream video playback audit

Audit date: 2026-11-04. Upstream is Djihads80/Eglantine, remote upstream. Initial base: origin/nx2 at 9a435b584a. Audited upstream nx2: a666e4400b. The final pre-push fetch still found that origin base and no merge/upstream-nx2-20261104 branch. The complete search result list is in the inventory.

Port decisions

SourceCommitDecision
#44497351edbfcPort per-stream H.264 framing and its four regression tests. Also reset framing on decoder Reset/Drain and use size_t for prefix advances. This PR is merged upstream but absent from the local base.
#39110d62f6661Port the environment-variable shadowing fix without changing EOS fence policy.
#123bde691ac7aPort parent-memory and image-offset presentation lookup. Adapt it to the fork's shared device ranges rather than reading the active Maxwell channel from the service thread. Keep handle metadata in the existing mapping list so remaps and partial unmaps cannot leave stale ranges.
#1239332056123Apply collected CPU writes before downloading GPU data.
#1231e6cfd5b4ePort the bounded synchronous-submit wait as an opt-in diagnostic. Do not enable the old Yoshi-specific default. This fork already snapshots submitted command words and has newer GPU-write synchronization.
#1182d3b628b2fPort only queued-EOS ready-event suppression. Keep the later #356 fence policy and this fork's existing stop/finalize and Mario Kart synthetic-EOS behavior. Do not port immediate release-fence completion.

These changes do not prove that the reported Yoshi or Kirby crash is fixed. No game dump, save, or owner crash log was available for a local reproduction. The new trace separates decoding, image writes, presentation, and skip/EOS handling.

Verification evidence

The original packet converter fails 268 of 1,070 assertions from #444's four tests. The port plus reset coverage passes 1,073 assertions across five tests in a standalone Catch2 build.

A generated ten-second, 640x360, 30 FPS H.264 MP4 with repeated parameter sets provides a separate FFmpeg check. The original converter produces 268 of 300 frames and 32 rejected packets. The port produces 300 of 300 frames, zero rejected packets, and identical per-frame pixel hashes to FFmpeg's normal MP4 decode. Annex-B input also produces 300 matching frames without rejected packets.

Three registry tests cover parent offsets, partial unmaps, remaps, and session reset. The full clang 20/Ninja RelWithDebInfo build passes with all eight available cores. CTest passes all 479 cases and 15,726,880 assertions. The focused H.264 and mapping selection passes eight cases and 1,089 assertions.

cmake -S . -B build -G Ninja \
  -DCMAKE_C_COMPILER=clang-20 -DCMAKE_CXX_COMPILER=clang++-20 \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DENABLE_QT=OFF -DYUZU_CMD=ON -DYUZU_TESTS=ON -DENABLE_WERROR=OFF
cmake --build build --parallel "$(nproc)"
ctest --test-dir build --output-on-failure -V
build/bin/tests '[h264],[nx2_mapping]'

The build used CMake 3.31.10 and system FFmpeg 6.1 with libdav1d. Clang 18 rejects the existing -mtls-dialect=gnu2 flag, so verification used clang 20 instead. Existing -Wno-error-all warnings remain. The CLI's --version smoke test exits successfully, though it emits empty-directory configuration diagnostics on this fresh machine. No game-playback validation is implied by that smoke test.

Related issue evidence

  • #311 and #407 report AV1 cutscenes skipped in MinGW/PGO builds while MSVC works.
  • #409 includes movie audio stutter and a later AV1 report where decoding advances faster than presentation. It does not establish that decoder pacing causes the audio problem.
